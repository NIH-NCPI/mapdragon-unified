# MapDragon Quick Start

If you are primarily interested in testing that your changes to the Dockerfile
are correct and have all of the intended changes, this is where you want to be.

## Prerequisites

This approach requires the following:

- [just](https://github.com/casey/just#installation)
- [Docker with Docker Compose](https://docs.docker.com/engine/install/ubuntu/)
  This is for ubuntu but there are instructions for other OS as well
- [uv](https://docs.astral.sh/uv/getting-started/installation/) to pull the FTD
  blueprint config or a config.yaml file

## Building the config file

The config.yaml file is used to seed the database with admin users,
institutions, ontology API stuff as well as some core terminologies. Members of
Carrollaboratory can use the following command to download a copy (which can
then be tweaked as needed)

```shell
uvx --from git+https://github.com/carrollaboratory/ftd-blueprint blue -c locutus-utils -o config.yaml
```

This spins up a temporary copy of ftd-blueprint and then has it download the
default locutus-utils config.yaml file. This file has user emails in it, so it
shouldn't be made available on a public repository. As a result, the blueprint
repo is locked down to members.

This file shouldn't be checked into a public repo.

## Just Recipes

From inside the mapdragon-unified repository, you can list all available
commands using **just** without specifying a recipe:

```shell
$ just
Available recipes:
    check-pins  # Show the pinned commits and refuse to build if anything overrides them
    default
    down        # Stop everything (keeps the local database)
    logs        # Follow the app logs
    reset       # Stop everything and wipe the local database for a clean test
    seed        # Seed the local mongo from config.yaml (institutions, admins, terminologies)
    seed-remote # Seed the remote database given by MONGO_URI in .env
    test        # Build from the Dockerfile pins, start everything, and seed the local DB
    up          # Build the image from the Dockerfile pins and start app + mongo
```

## Testing out the image

Once you have a valid config file (such as generated by the above command), you
can spin the image up and do your testing. Please note that this assumes you
have edited the Dockerfile with the apprpropriate commit hashes and version
information.

To simplify a lot of things, there is now a justfile that provides a single
command to bring up the database, seed it and then the application itself:

```shell
just test
```

FWIW, there has always been a pretty lengthy delay before the web finally
responds. I assume that is a combination of the seeds and other stuff happening
in the background after the just script says everything is ready. So, don't
panic if it hasn't responded, even after a few minutes.

When you have finished, you can bring the whole thing down using **just down**.

```shell
just down
```

Finally, if you want to clean your database, you can do so using **just reset**.

```shell
just reset
```
